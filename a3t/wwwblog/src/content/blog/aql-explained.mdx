AQL is the query language agents use for their own memory: five memory types (working, episodic, semantic, procedural and tools) and a small set of verbs to store, recall, link and learn. [Agent Memory Needs a Query Language](../agent-memory-needs-a-query-language/) explains why. This post is the reference.

AQL is not YAML, so instead of keys the tree is built from verbs. Every statement has the same shape:

```sql
VERB  FROM|INTO  MEMORY_TYPE  predicate  [modifiers...]
```

Each verb below opens into those parts in order: the memory it reads or writes, the predicate that picks records, then the modifiers that shape the result. Click **+** on any part to see what it does and an example.

## Three rules that hold everywhere

1. **Direction is in the words.** Reads take `FROM` memory, `STORE` and `UPDATE` write `INTO` it, and `FORGET` removes `FROM` it. `LINK` says both ends: `FROM` one record `TO` another.
2. **Every statement names its memory.** A write names exactly one type. `ALL` works with `RECALL`, `REFLECT` and `FORGET` only, and `FORGET` always needs `WHERE`.
3. **Modifiers come after the predicate, in any order.** `LIMIT 5 ORDER BY time DESC` and `ORDER BY time DESC LIMIT 5` mean the same.

Every example in the tree parses with the AQL reference parser. The [browser playground](https://srirammails.github.io/AQL/playground/) runs the core language; the stream verbs, `GROUP BY`, `WINDOW` on `RECALL` and the time modifiers already run in the parser and in ADB, A3T's memory engine, but not yet in the playground.
